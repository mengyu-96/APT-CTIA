# 实体和关系增强说明

## 一、新增实体类型（10种）

### 1. 攻击活动实体

#### OPERATION（攻击行动）
- **模式**: `r"\bOperation\s+[A-Z][a-zA-Z0-9\s-]+\b"`
- **示例**: Operation Aurora, Operation Pawn Storm, Operation Blockbuster
- **用途**: 标识具体的攻击行动

#### CAMPAIGN（攻击活动）
- **模式**: `r"\b(?:Campaign|行动|活动)[\s:：]?([A-Z][a-zA-Z0-9\s-]+)\b"`
- **示例**: Campaign XYZ, 行动代号
- **用途**: 标识攻击活动

### 2. 基础设施实体（新增）

#### SSL_CERT（SSL/TLS证书）
- **模式**: `r"\b(?:SSL|TLS|证书|certificate)[\s:：]?(?:serial|序列号)?[\s:：]?([a-fA-F0-9:]{20,})\b"`
- **示例**: SSL certificate serial: 00:11:22:33:44:55
- **用途**: 提取与恶意基础设施关联的证书

#### HOSTNAME（主机名）
- **模式**: `r"\b(?:host|主机|server|服务器)[\s:：]?([a-zA-Z0-9][a-zA-Z0-9\-\.]+)\b"`
- **示例**: server01.internal.com, host victim-pc
- **用途**: 提取被入侵的主机

### 3. 目标与受害者实体（新增）

#### INDUSTRY（行业）
- **模式**: `r"\b(?:金融|能源|医疗|政府|教育|制造业|technology|financial|energy|healthcare|government|education|manufacturing|defense|telecommunications)\b"`
- **示例**: 金融, financial, energy, healthcare
- **用途**: 提取目标行业

#### CITY（城市）
- **模式**: `r"\b(?:北京|上海|广州|深圳|杭州|南京|武汉|成都|西安|重庆|New York|London|Moscow|Tokyo|Berlin|Paris|Washington|Beijing|Shanghai)\b"`
- **示例**: 北京, New York, London
- **用途**: 提取目标地理位置（城市级别）

#### USER_ACCOUNT（用户账户）
- **模式**: `r"\b(?:user|用户|account|账户|username)[\s:：]?([a-zA-Z0-9_\.\-@]+)\b"`
- **示例**: administrator@victim.com, user admin
- **用途**: 提取被窃取或滥用的账户

### 4. 漏洞实体（新增）

#### CWE（弱点）
- **模式**: `r"\bCWE-\d+\b"`
- **示例**: CWE-78, CWE-79
- **用途**: 提取通用弱点枚举

### 5. 情报来源实体（新增）

#### THREAT_INTEL_SOURCE（威胁情报来源）
- **模式**: `r"\b(?:FireEye|CrowdStrike|Mandiant|Kaspersky|Symantec|Trend Micro|Palo Alto|奇安信|360|安天|微步在线|VirusTotal|AlienVault|OTX|MITRE|ATT&CK)\b"`
- **示例**: FireEye, CrowdStrike, 奇安信
- **用途**: 标识威胁情报报告来源

## 三、语义关系边构建（10种关系）

### 3.1 归属/隶属于关系

**关系类型**: `belongs_to`

**规则**:
- OPERATION/CAMPAIGN → REPORT（攻击活动隶属于报告）
- IP/DOMAIN → 攻击者（通过共现推断）

**实现**:
```python
# 攻击活动连接到报告根节点
operation_nodes → report_root_node
```

### 3.2 使用关系

**关系类型**: `uses`

**规则**:
- MALWARE/TOOL → MITRE_TECH（恶意软件/工具使用攻击技术）
- OPERATION/CAMPAIGN → CVE（攻击活动利用漏洞）

**实现**:
```python
# 恶意软件/工具连接到MITRE技术
malware_nodes → mitre_nodes
tool_nodes → mitre_nodes

# 攻击活动连接到CVE
operation_nodes → cve_nodes
```

### 3.3 通信/连接关系

**关系类型**: `connects_to`

**规则**:
- HASH → IP/DOMAIN/URL（恶意软件样本连接C2服务器）

**实现**:
```python
# 恶意软件样本连接到基础设施
hash_nodes → ip_nodes + domain_nodes + url_nodes
```

### 3.4 投放/传播关系

**关系类型**: `delivers`

**规则**:
- EMAIL → HASH（钓鱼邮件投放恶意软件）
- CVE → HASH（漏洞利用传播恶意软件）

**实现**:
```python
# 邮件连接到恶意软件
email_nodes → hash_nodes

# 漏洞连接到恶意软件
cve_nodes → hash_nodes
```

### 3.5 关联/匹配关系

**关系类型**: `related_to`

**规则**:
- IP ↔ DOMAIN（IP解析为域名）
- HASH ↔ HASH（相似恶意软件样本）

**实现**:
```python
# IP和域名互连
ip_nodes ↔ domain_nodes

# 恶意软件样本互连
hash_nodes ↔ hash_nodes (两两连接)
```

### 3.6 持久化关系

**关系类型**: `persists_via`

**规则**:
- HASH → REGISTRY（恶意软件通过注册表持久化）
- HASH → FILE_PATH（恶意软件文件路径）

**实现**:
```python
# 恶意软件连接到持久化机制
hash_nodes → registry_nodes
hash_nodes → file_path_nodes
```

### 3.7 目标关系

**关系类型**: `targets`

**规则**:
- OPERATION/CAMPAIGN → INDUSTRY/COUNTRY/CITY/ORG（攻击活动目标）

**实现**:
```python
# 攻击活动连接到目标
operation_nodes → industry_nodes + country_nodes + city_nodes + org_nodes
```

### 3.8 执行关系

**关系类型**: `executes`

**规则**:
- TOOL → MITRE_TECH（工具执行攻击技术）

**实现**:
```python
# 工具连接到攻击技术
tool_nodes → mitre_nodes
```

### 3.9 指示关系

**关系类型**: `indicates`

**规则**:
- FILE_PATH/REGISTRY/PROCESS → HASH（指标指示恶意软件）

**实现**:
```python
# 指标连接到恶意软件
indicator_nodes → hash_nodes
```

### 3.10 隶属于同一活动关系

**关系类型**: `same_activity`

**规则**:
- 同一段落内的所有实体隶属于同一活动

**实现**:
```python
# 如果段落中有OPERATION/CAMPAIGN，连接该段落所有实体
if paragraph_has_operation:
    connect_all_entities_in_paragraph
```

## 七、技术细节

### 7.1 实体提取优先级

实体提取按以下顺序进行：
1. 正则表达式匹配（基础IOC、攻击技术、漏洞等）
2. 新增实体类型匹配（攻击活动、SSL证书等）
3. 词典匹配（恶意软件、工具、组织等）

### 7.2 边构建优先级

边构建按以下顺序进行：
1. 段落内共现边（基础）
2. 跨段落连接（增强连通性）
3. 语义关系边（新增，基于实体类型）
4. 根节点连接（确保连通性）
5. 单实体/小图处理（兜底策略）

### 7.3 性能考虑

- **实体提取**: 新增10种实体类型，预计处理时间增加10-15%
- **图构建**: 新增10种语义关系，预计边数增加30-50%
- **内存占用**: 预计增加5-10%（更多实体和边）
