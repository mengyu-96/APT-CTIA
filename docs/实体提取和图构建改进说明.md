# 实体提取和图构建改进说明

## 一、实体提取规则改进

### 1.1 改进现有实体类型提取

#### IP地址提取优化
- **原模式**: `r"\b(?:\d{1,3}\.){3}\d{1,3}\b"` - 可能匹配到版本号（如1.2.3.4）
- **新模式**: `r"\b(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\b"`
- **改进**: 严格验证IP地址范围（0-255），避免误匹配

#### HASH值提取优化
- **原模式**: `r"\b[a-fA-F0-9]{32}\b"` - 可能匹配普通十六进制字符串
- **新模式**: 使用负向前后查找，确保HASH值前后有分隔符
  - MD5: `r"\b(?<![\da-fA-F])[a-fA-F0-9]{32}(?![\da-fA-F])\b"`
  - SHA1: `r"\b(?<![\da-fA-F])[a-fA-F0-9]{40}(?![\da-fA-F])\b"`
  - SHA256: `r"\b(?<![\da-fA-F])[a-fA-F0-9]{64}(?![\da-fA-F])\b"`
- **改进**: 减少误匹配，提高准确率

### 1.2 新增实体类型（8种）

#### 1. URL实体
- **模式**: `r"\bhttps?://[^\s<>\"{}|\\^`\[\]]+"`
- **用途**: 提取C2服务器URL、下载链接等
- **标签**: `URL`

#### 2. 文件路径实体
- **模式**: `r"\b(?:[A-Za-z]:)?(?:[/\\][\w\s\-_.]+)+\.(?:exe|dll|bat|cmd|ps1|vbs|js|jar|py|sh|bin|scr|com|pif|lnk)\b"`
- **用途**: 提取恶意文件路径、系统路径等
- **标签**: `FILE_PATH`

#### 3. 注册表项实体
- **模式**: `r"\b(?:HKEY_|HKLM|HKCU|HKCR|HKU|HKCC)[\\\w\s\-_.]+"`
- **用途**: 提取注册表持久化路径
- **标签**: `REGISTRY`

#### 4. 端口号实体
- **模式**: `r"\b(?:port|端口)[\s:：]?(\d{1,5})\b"`
- **用途**: 提取C2端口、服务端口等
- **标签**: `PORT`

#### 5. 进程名实体
- **模式**: `r"\b(?:process|进程)[\s:：]?([A-Za-z][\w\s\-_.]+\.(?:exe|dll|bat|cmd|ps1))\b"`
- **用途**: 提取恶意进程名称
- **标签**: `PROCESS`

#### 6. 服务名实体
- **模式**: `r"\b(?:service|服务)[\s:：]?([A-Za-z][\w\s\-_.]+)\b"`
- **用途**: 提取Windows服务名称
- **标签**: `SERVICE`

#### 7. 用户代理实体
- **模式**: `r"\bUser-Agent[\s:：][^\n\r]+"`
- **用途**: 提取HTTP User-Agent字符串
- **标签**: `USER_AGENT`

#### 8. 文件扩展名实体
- **模式**: `r"\b\.(?:exe|dll|bat|cmd|ps1|vbs|js|jar|py|sh|bin|scr|com|pif|lnk|doc|docx|xls|xlsx|pdf|zip|rar|7z)\b"`
- **用途**: 提取文件类型信息
- **标签**: `FILE_EXT`

### 1.3 实体类型统计

**改进前**: 12种实体类型
- IP, DOMAIN, EMAIL, HASH_MD5, HASH_SHA1, HASH_SHA256, MITRE_TECH, CVE, MALWARE, TOOL, ORG, COUNTRY

**改进后**: 20种实体类型
- 原有12种 + 新增8种（URL, FILE_PATH, REGISTRY, PORT, PROCESS, SERVICE, USER_AGENT, FILE_EXT）

## 二、图构建逻辑优化

### 2.1 原有问题

1. **单实体无法构图**: 需要至少2个实体在同一段落才能构建边
2. **跨段落信息丢失**: 实体在不同段落出现时无法建立连接
3. **小图信息不足**: 节点数<5的图结构过于简单
4. **边构建条件过严**: 导致大量报告无法生成图

### 2.2 优化策略（5种）

#### 策略1: 段落内共现边（保留并改进）
- **原有逻辑**: 段落内至少2个实体才连接
- **改进**: 
  - 段落内≥2个实体：两两连接
  - 段落内=1个实体：添加自环边（新增）

#### 策略2: 跨段落连接（新增）
- **逻辑**: 如果实体在多个段落出现，连接这些段落的所有实体
- **优势**: 捕获跨段落的实体关系，提高图连通性
- **实现**: 
  ```python
  # 找到出现在多个段落的实体
  # 连接这些段落中的所有实体
  ```

#### 策略3: 报告根节点连接（保留）
- **逻辑**: 报告根节点连接所有实体节点
- **作用**: 确保图的连通性

#### 策略4: 单实体图处理（新增）
- **问题**: 只有一个实体时无法构建边
- **解决**: 
  - 添加自环边
  - 如果启用根节点，连接根节点和实体

#### 策略5: 小图增强（新增）
- **条件**: 节点数<5且>1
- **策略**: 为小图添加全连接（所有实体两两连接）
- **优势**: 提高小图的特征表示能力

### 2.3 边构建流程

```
1. 段落内共现边
   ├─ ≥2个实体 → 两两连接
   └─ 1个实体 → 自环边

2. 跨段落连接
   └─ 多段落实体 → 连接相关段落的所有实体

3. 根节点连接
   └─ 根节点 ↔ 所有实体节点

4. 单实体处理
   └─ 自环边 + 根节点连接

5. 小图增强（节点<5）
   └─ 全连接（所有实体两两连接）

6. 最后保障
   └─ 如果仍无边，添加自环边
```

## 四、使用建议

### 4.1 推荐配置

```bash
# 使用改进后的实体提取和图构建
python preprocess_apt_dataset.py \
  --pdf-root dataset_PDF \
  --txt-root dataset_TXT \
  --output-dir processed_improved \
  --only-txt \
  --min-entities 1 \              # 降低阈值，利用单实体图处理
  --min-paragraph-length 10 \     # 降低段落长度要求
  --feature-dim 64
```

### 4.2 验证改进效果

1. **实体统计**: `processed_improved/entities.jsonl` 中的实体类型分布
