# 问题诊断报告：模型指标为0和构图成功率低

## 一、模型指标为0的问题分析

### 1.1 问题现状

**发现的问题**：
- `models/gnn_txt_only/test_results.json` 显示所有指标为0
  - 准确率: 0.0
  - F1-weighted: 0.0
  - F1-macro: 0.0

### 1.2 可能原因分析

#### 原因1: 测试集为空或未正确加载 ⚠️ **最可能**
- **症状**: 测试集可能没有数据，导致评估时没有样本
- **检查方法**: 查看训练日志，确认测试集大小
- **解决方案**: 重新运行训练，确保数据正确划分

#### 原因2: 模型未正确加载 ⚠️ **很可能**
- **症状**: `best_model.pt` 文件不存在、损坏或路径错误
- **检查方法**: 
  ```bash
  ls models/gnn_txt_only/best_model.pt
  ```
- **解决方案**: 重新训练模型，确保模型文件正确保存

#### 原因3: 数据划分问题 ⚠️ **可能**
- **症状**: 随机划分导致测试集中某些类别完全缺失
- **检查方法**: 检查测试集中是否包含所有类别
- **解决方案**: 使用 `--stratified` 参数进行分层采样

#### 原因4: 标签映射不匹配 ⚠️ **可能**
- **症状**: 训练和测试时使用了不同的标签映射文件
- **检查方法**: 对比训练时和测试时的 `label_mapping.json`
- **解决方案**: 确保使用相同的标签映射文件

#### 原因5: 模型训练失败 ⚠️ **不太可能**
- **症状**: 模型所有预测都是错误的（但通常不会是0.0，而是接近随机猜测）
- **检查方法**: 查看训练日志，检查验证集准确率
- **解决方案**: 检查训练过程，调整超参数

## 二、构图成功率低的问题分析

### 2.1 问题现状

**数据统计**：
- **原始文件数**: 238个TXT文件
- **成功构图数**: 
  - `processed_txt_only` (min_entities=3): **76个 (31.9%)**
  - `processed_txt_min1` (min_entities=1): **138个 (58.0%)**
- **失败原因**: 162个文件（68.1%）或100个文件（42.0%）未能生成图

### 2.2 根本原因分析

#### 原因1: 实体数量不足 ⚠️ **主要原因**

**问题**：
- 默认 `min_entities_per_graph = 3`，要求每个报告至少3个实体才能构图
- 统计显示：**34.8%的报告实体数 < 3**
- 平均每个报告只有8.3个实体

**证据**：
```
报告实体数量分布:
  平均: 8.3
  最小: 1
  最大: 112
  实体数<3的报告: 48 (34.8%)  ← 这些报告无法构图（min_entities=3时）
  实体数<1的报告: 0 (0.0%)
```

**解决方案**：
1. ✅ **已实施**: 使用 `--min-entities 1` 可以将构图率从31.9%提升到58.0%
2. 进一步降低阈值（但可能导致图质量下降）

#### 原因2: 实体类型单一 ⚠️ **次要原因**

**问题**：
- 当前只提取了3种主要实体类型：
  - DOMAIN: 849个（最多）
  - CVE: 209个
  - MITRE_TECH: 87个
- 缺少IP、HASH、EMAIL等实体类型（可能提取规则不完善）

**证据**：
```
实体类型统计:
  DOMAIN    : 849 个, 出现在 116 个报告中
  CVE       : 209 个, 出现在 51 个报告中
  MITRE_TECH:  87 个, 出现在 1 个报告中
```

**解决方案**：
1. 检查实体提取规则，确保IP、HASH、EMAIL等类型被正确提取
2. 添加更多实体类型（文件路径、注册表项等）
3. 使用NER模型提高实体识别准确率

#### 原因3: 文本质量问题 ⚠️ **可能原因**

**问题**：
- 部分文件可能为空或格式异常
- 编码问题导致文本提取失败
- 文本内容不包含技术细节（如只有摘要）

**检查方法**：
```bash
# 查看跳过的文件
cat processed_txt_only/skipped_reports.jsonl
```

**解决方案**：
1. 改进文本预处理，处理编码问题
2. 降低 `min_paragraph_length` 阈值（当前默认20）
3. 对于实体极少的文件，考虑使用全文特征

#### 原因4: 图构建逻辑限制 ⚠️ **技术原因**

**代码逻辑**（`preprocess_apt_dataset.py:836-865`）：
```python
# 条件1: 实体数量不足
if num_entities < self.config.min_entities_per_graph:
    return None

# 条件2: 无法构建边（需要至少2个实体在同一段落）
if not edge_set:
    return None
```

**问题**：
- 即使有实体，如果实体不在同一段落，也无法构建边
- 单实体报告无法构图（需要至少2个实体才能有边）

**解决方案**：
1. 对于单实体报告，添加自环边
2. 放宽边构建条件（如跨段落连接）
3. 使用虚拟边连接所有实体

### 2.3 构图成功率对比

| 配置 | min_entities | 成功构图 | 成功率 | 说明 |
|------|-------------|---------|--------|------|
| `processed_txt_only` | 3 (默认) | 76/238 | 31.9% | 标准配置 |
| `processed_txt_min1` | 1 | 138/238 | 58.0% | 降低阈值 |
| **提升** | -2 | +62 | +26.1% | **显著提升** |

**结论**: 降低 `min_entities` 阈值可以显著提高构图成功率！

### 2.4 小图问题

**统计**：
- `processed_txt_min1`: 85/138 (61.6%) 的图节点数 < 5
- 这些图结构简单，可能影响模型学习效果

**影响**：
- 小图特征表示能力弱
- GNN难以从稀疏图中学习有效模式

**解决方案**：
1. 图增强技术（添加自环、K-hop连接）
2. 特征增强（添加图级别统计特征）
3. 使用更适合小图的模型架构
